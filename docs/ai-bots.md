# AI 机器人：企业微信、钉钉与后续飞书

优先级：企业微信、钉钉先接入；飞书后续实现。首版提供双向文字问答，接收平台消息、调用已配置的 AI 智能体、返回回答，不是群通知 Webhook。

## 当前能力

- AI 助手下新增「机器人」，可创建、编辑、启用、禁用、删除；企业微信和钉钉均显示连接、最近心跳与重连状态。
- 企业微信使用 Bot ID + Secret 的 WebSocket 长连接，主动订阅、心跳保活、断线重连，并通过同一连接发送流式回答，无需公网回调地址。
- 钉钉使用 Client ID + Client Secret 的 Stream 长连接接收机器人消息；先持久化回执并确认接收，再通过临时 HTTPS sessionWebhook 发送一次文字回答，无需公网接收地址。
- 复用绑定智能体的供应商、模型、系统提示词和技能；按机器人、智能体、会话、发送人分别保存历史。同群不同发送人的上下文不共享，群聊与单聊不共享。
- 平台重发同一消息时复用持久化回执，不重复调用 AI。失败、回复失败和中断均不自动重放；需要用户重新发送新消息。同一会话的消息按接收记录顺序执行。
- 平台身份尚未映射到内部用户权限，因此机器人入口不加载本地工具或 MCP。内部网页聊天继续使用原有工具能力。
- 飞书在页面标为「后续支持」，服务端拒绝创建飞书配置。

## 接入准备

1. 启动新版服务，自动建表并补齐 AI 助手下的机器人菜单及查询、新增、编辑、删除权限。已有管理员重新登录或刷新菜单；普通角色须分配机器人接口权限，以及用于选择智能体的查询权限。
2. 在「供应商」中配置可用模型，在「智能体」中配置并启用问答智能体。
3. 企业微信需能出站连接 `wss://openws.work.weixin.qq.com`；钉钉需访问 `api.dingtalk.com:443`、`wss-open-connection.dingtalk.com:443`，回答还需访问临时会话地址的 `oapi.dingtalk.com:443`。两者均无需开放公网入站回调端口。
4. 新建机器人，选择平台和智能体，按平台填写 Bot ID + Secret 或 Client ID + Client Secret。默认禁用，完成平台设置后启用并检查连接状态。

管理接口受 JWT 与 Casbin 保护；两个平台的长连接分别使用平台凭据鉴权，不使用内部用户 JWT。旧 HTTP 接收入口已停用。

## 企业微信

1. 创建**智能机器人**，开启 API 模式并选择**长连接**。普通群自定义通知机器人不能用于接收 AI 提问。
2. 取得长连接专用 **Bot ID 和 Secret**，填入本系统企业微信机器人配置。这与旧回调模式的 Token、EncodingAESKey 不同。
3. 选择智能体、设置平台可见范围并启用本系统机器人。服务会连接企业微信，发送 `aibot_subscribe` 并等待认证成功。
4. 查看连接状态变为「已连接」，在单聊中发送文字，或在群聊中 @ 机器人发送文字。机器人先回复「正在思考」，模型生成期间更新回答，最后发送 `finish=true` 结束。
5. 若需要文档、智能表格能力，先阅读下方官方授权说明；该业务授权与文字问答连接鉴权分别配置。

消息仅处理 `text`，图片、语音、文件、混合消息不触发模型。长连接无需 stream 刷新回调，回答由服务主动发送。回复按 UTF-8 边界限制到 20,480 字节，认证、心跳和回复均按 `req_id` 关联回执；缺失或非零 `errcode` 不视为成功。

按真实平台会话统一控制 **30 次/分钟、1000 次/小时** 的滚动发送额度；群聊内不同成员共享额度，初始消息、流式刷新、结束帧和繁忙回复均保守计入。发送记录存入数据库，重启和更换 Secret 不会重置额度。额度不足时跳过中间刷新并保留累计内容，初始和最终回答可等待额度；等待超时则记录回复失败，不超额重发。

重复消息仅去重，不重新发送初始或终结帧；每条独立消息使用独立 stream ID，成功结束后不再更新。传输层分别检查回调收到后 24 小时的回复窗口和 stream 首发后 10 分钟的刷新窗口。业务层将企业微信整条处理（含限额等待）限制为 9 分钟，模型执行及排队仍最多 90 秒，以预留结束时间。带有 `compat_info` 的智能助理、频道等非普通用户来源当前忽略，不混入普通用户会话。

每 30 秒发送应用层 `ping`；心跳回执丢失时断开异常连接并重连。网络失败采用带抖动的指数退避，基础延迟 1 秒，最大 30 秒，直到恢复或机器人被停用。明确认证失败显示「认证失败」，需核对凭据后保存；收到其他连接接管的 `disconnected_event` 后显示「连接被接管」并停止自动重连，避免两个实例持续抢占。每个 Bot ID 只配置一条记录，多个服务实例应只由其中一个实例管理该机器人，主备接管需另行协调。

保存配置、禁用、删除和服务退出会取消对应连接及在途任务，释放心跳、重连和消息处理资源。重连不会把旧连接的晚到 AI 回答发送到新连接；不确定的回复不自动补发，用户可重新发送新消息。

只轮换同一个 Bot ID 的 Secret 会保留该机器人的对话；更换 Bot ID 时，历史上下文和消息去重分别隔离，避免把旧机器人所属企业的对话带入新机器人。

### 文档与智能表格授权：按官方文档操作

请配置人员阅读[企业微信《API模式机器人文档使用说明》](https://developer.work.weixin.qq.com/document/path/101468)。官方当前授权入口为「工作台 → 智能机器人 → 对应机器人 → 编辑 → 可使用权限 → 授权」；成功后进入「查看使用方式」，获取文档 MCP 的 streamableHTTP URL 或 JSON Config。

文档授权有效期为 **7 天**，该期限不表示 Bot ID + Secret 每 7 天失效。机器人仅能编辑自己创建的文档，不能据此访问成员的全部文档。详见[连接与业务授权分层说明](wecom-authorization.md)。

**本系统目前仅开放文字问答，尚未加载机器人文档 MCP。** 完成平台文档授权不会自动开启本系统的文档操作能力；不要将文档 MCP URL 或 JSON Config 填入 Bot ID、Secret 表单。页面已提供官方文档链接和对应提示。

### 从旧企业微信 HTTP 配置迁移

新版企业微信入口仅使用长连接。已有 Token/EncodingAESKey 记录不会自动转换成 Bot ID/Secret，需在平台切换连接方式并重新填写凭据；缺少长连接凭据的旧记录显示「待配置」，不会尝试连接。企业微信不再处理原 HTTP 消息回调。

## 钉钉

1. 在开放平台创建企业内部应用，添加机器人能力。
2. 将机器人消息接收方式设为 **Stream 模式**，保存配置，设置可见范围并发布应用。
3. 从应用凭证取得 **Client ID（AppKey）** 和 **Client Secret（AppSecret）**，填入本系统并选择智能体；不是自定义通知机器人的 SEC 加签密钥。
4. 启用后确认状态为「已连接」。在单聊中发送文字，或在群聊中 @ 机器人发送文字问题。

每次连接先向钉钉取得短期单次 ticket，使用服务返回的 WSS 地址连接，只订阅机器人消息 topic。每次网络重连均重新取票；系统心跳按钉钉 `SYSTEM/ping` 原样回显 opaque，平台 `disconnect` 属于正常连接管理，应处理在途消息后重新注册连接，不能套用企业微信的接管停连规则。另有本地空闲探活和指数退避重连，配置修改、禁用、删除及退出会取消对应连接和任务。

收到有效消息后，先持久化去重回执并异步启动 AI，再确认 Stream 接收，不等待模型生成。钉钉当前机器人通道为 fire-forgot，不把 ACK 失败当成可靠重投队列；满载时保留回执并尝试回复一次繁忙消息，避免同条消息重复执行。模型完成后，向该消息携带的临时 `sessionWebhook` 发送一次文字回答，**接收长连接不等于回答打字机效果**。

临时地址过期时间按 `sessionWebhookExpiredTime` 的实际值判断，不硬编码统一时长。HTTP 失败、缺少 `errcode` 或非零错误码均视为回复失败，不盲目补发。

出站仅允许官方示例地址 `https://oapi.dingtalk.com/robot/sendBySession?session=...`（可显式使用 443 端口），禁止重定向、其他域名、用户信息、fragment 和其他路径。消息回复按 UTF-8 边界限制到 16,000 字节。

同一 Client ID 只保留一条配置；轮换同应用的 Secret 保留历史，更换 Client ID 必须重新填写 Secret，并隔离旧应用的上下文和消息去重。缺少 Client ID 的旧 HTTP 记录显示「待配置」并不启动连接，需补齐凭据并在钉钉改为 Stream、保存发布。完整官方依据和步骤见[钉钉 Stream 接入说明](dingtalk-stream.md)。

## 运行行为与验证

后台最多同时处理 8 条模型请求，最多接纳 32 条在途模型任务。队列已满时，两平台均保留去重回执并尝试回复繁忙；不依赖机器人回调自动重投。模型执行及排队最多 90 秒，同一会话的后续消息等待前序任务完成。企业微信另有最多 9 分钟的发送等待与处理期限；钉钉回执超过 2 分钟后视为中断。进程重启后未完成的回执不自动重放。两平台禁用均会取消对应连接和任务。

机器人密钥不通过列表或保存响应回显，编辑时留空保留现有密钥。机器人配置请求体和回调内容不进入操作日志；失败的凭据写入也关闭 SQL 值日志。密钥按现有项目方式保存在数据库中，数据库及备份需要限制访问。

处理结果写入 `sys_ai_bot_deliveries`，状态包括 `processing / completed / failed / reply_failed / interrupted`；服务日志记录不含原文及密钥的 `ai_bot_delivery` 结果。机器人会话可在现有「会话」中查看，删除机器人保留已经生成的会话历史。独立删除会话后，下一条消息会新建会话。

本地自动化验证使用内存 SQLite、mock WebSocket 服务、httptest 和 mock 模型/平台响应，覆盖订阅认证、心跳、重连、接管、取消、旧连接回复拒绝、结束流及过期流拒绝、会话隔离、重复回调无二次终结、分钟/小时发送额度、额度跨重启保留、工具禁用和密钥脱敏。逐条依据与边界见[官方要求核对清单](wecom-long-connection-audit.md)。真实平台的凭据、发布、可见范围、文档授权与实际收发仍需分别联调；本地测试不代表已完成这些验收。

钉钉另验证取票与单次 ticket、Stream ACK、服务器心跳、平台断连与在途回调处理、旧 HTTP 停用、Client ID 轮换和临时地址回复的业务错误码。卡片、事件订阅、主动通知和真实企业环境仍不在本地 mock 验收结论内。
