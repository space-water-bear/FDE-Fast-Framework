# 页面与业务生成技能

项目提供三个可组合的内置技能。它们沿用 `AiSkill.Prompt` 注入机制，不引入另一套组件引擎或运行框架。

| 技能 | 适用需求 | 负责内容 |
|---|---|---|
| `fde-page-builder` | 新增/修改列表、表单、详情、树表与统计组合页 | 组件选择、页面交互、字段映射、状态展示和前端验证 |
| `fde-business-logic` | 校验、提交/完成等业务动作、关联保存与统计接口 | 服务端规则、权限归属、事务、必要的并发/幂等及数据兼容 |
| `fde-chart-builder` | 趋势、对比、构成图及统计交互 | ECharts 配置、聚合口径、筛选、图表状态和实例验证 |

## 使用方式与执行边界

重启后端后，初始化会补齐缺失技能，在“AI 助手 → 技能”中查看。进入目标智能体配置，按需求选择技能。列表/表单模块可绑定前两项；包含统计分析时可再绑定图表技能。初始化保留同名技能的人工编辑和已有智能体绑定。

技能说明中的核心组件和接口规则是自包含的。文档链接是有文件读取工具时的补充资料，不代表智能体自动拥有仓库访问权限，也不会自动加载另一个未绑定的技能。维护项目内提示词后，已有数据库中的同名技能保持原内容；需要在技能管理中合并新说明，不通过启动覆盖管理员修改。

当前内置工具只有示例天气工具，以及 `generate_form_schema`、`generate_business_code`、`apply_files`。基础 CRUD 模板尚未使用 TablePage/FormRender，枚举与关联字段会被 CRUD 投影跳过并返回 warning。`apply_files` 读取已保存审计批次，不是任意文件编辑工具。

源码检索、局部编辑、测试、构建和预览取决于智能体实际绑定的工具/MCP。缺少相关工具时，技能应输出可审阅的业务说明、代码和待执行项；不得声称已经写盘、通过测试或完成发布。工程执行能力的后续建设见 [交付路线图](agent-delivery-roadmap.md)。

## 页面和逻辑共用的业务说明

先将需求整理为一份业务说明，再映射为页面和后端实现。沿用已有项目的规格文件格式即可，不新增通用工作流 DSL。

| 内容 | 需要明确的契约 |
|---|---|
| 实体与字段 | 稳定 key、类型、默认值、可写范围、枚举、关系与引用约束 |
| 查询与展示 | 筛选字段、分页、列表列、详情、编辑区块及数据来源 |
| 动作与状态 | 稳定操作 key、允许的前后状态、必填条件、成功/失败行为 |
| 角色与归属 | 哪些角色可以操作，以及能够访问哪些记录 |
| 接口 | 请求 DTO、业务结果、字段映射、错误与重试语义 |
| 图表 | 指标、维度、聚合范围、币种/单位、退款、业务日时区、补零与分母 |
| 验收 | 正常路径、非法输入/状态、越权、失败恢复及必要的并发案例 |

例如 `repair.complete` 在页面上显示“完成”，服务端按相同规格验证当前状态和处理结果；显示文字不作为操作标识。按钮显隐提供反馈，JWT/Casbin 和记录归属由后端独立检查。

Schema 工具字段名要求小写 snake_case，API JSON 使用项目既有 camelCase，编辑回填与提交需要显式双向映射；保留旧字段兼容。Schema 保存会替换完整字段集合，`mode:update` 不等于局部合并；更新前读取完整对象，合并保留所有原字段和规则，保存后重新核对。代码生成 dry-run 会写生成审计，不能当成完全只读操作。

## 组件生成规范

| 场景 | 优先使用 | 核心契约 |
|---|---|---|
| 查询、分页、树表 | `TablePage` | `fetch({page,pageSize,...filters}) → {list,total}`；事件连接业务动作，列插槽展示专用单元格 |
| Schema 字段表单 | `FormRender` | `schema + v-model`；默认值由页面初始化；提交校验必须接到实际可用的验证流程 |
| 专用或复杂业务表单 | 组合 Element Plus `el-form` 等 | 显式实现跨字段、公式、远程级联和提交前校验 |
| 趋势、对比、构成 | `BaseChart` 与三个配置函数 | 传完整 `option` 和状态；页面负责聚合接口及筛选，组件负责生命周期 |
| 详情、弹窗、文件上传 | 现有 Element Plus 组件及项目 API | 核对同类页面与接口，不假设存在未实现的专用封装 |

TablePage、FormRender、ECharts 和 Element Plus 可以在同一个业务页面组合，不要求每种页面再封装一层。先看项目实际导出，再生成 import、props、事件和 ref 调用。

### TablePage

```ts
import { TablePage } from '@/components/table-page'
import type { TableQuery, SearchField } from '@/components/table-page'
```

- 搜索和树筛选由组件内部重置分页，避免重复请求；新增/编辑成功后调用 ref 的 `reload()`。
- TablePage 的 `reload()` 不接收 `keepPage` 参数。确需操作分页时，通过其实际 `getGrid()` 接口核对实现；不把 TablePageGrid 的方法签名直接套到 TablePage。
- 工具按钮的 `code`、行操作 key 和业务动作对应；按现有权限数据判断可见性，后端仍鉴权。
- [详细组件契约](components/table-page.md)。

### FormRender 的当前能力

```ts
import FormRender from '@/components/form-render/FormRender.vue'
import type { FormSchema } from '@/components/form-render/types'
```

Schema 的 `fields` 是字段对象，每字段 `required` 为布尔值，布局和控件使用 `x-ui`。不存在目录 `index.ts` 导出，当前也没有公开的 `validate/resetFields/clearValidate` 方法。

用于需要提交的表单时，可以采用已有 Element Plus 表单验证；或在实际开发任务中补齐、验证 FormRender 的公开整体验证能力后再调用。不能仅因界面展示了必填标记就宣称提交前校验有效。服务端同样执行字段与业务约束。

- 默认值需显式初始化 model，Schema 的 `default` 不会自行填入。
- 联动只支持 `when.field/eq → then.field/visible/required`，赋值和公式需页面代码实现。
- `table-select` 是本地选项过滤单选，不是远程分页关联选择器。
- 静态 `x-ui.options` 优先于 `enum`；字典查询按数字 `typeId` 接入。前端虽然容许字典编码参数，当前后端没有相应编码解析，不能据此生成可用承诺。
- 当前业务对象/Schema 保存路径仍有交付路线图列出的契约缺口。保存后重新读取核对规则，不能只检查生成时的 JSON。

### ECharts

```ts
import { BaseChart, createLineOption, createBarOption, createDonutOption } from '@/components/charts'
```

三类图表与列表共享筛选语义；图表使用后端全量聚合接口，列表分页只用于列表。金额单位转换集中在展示边界，真实零值与无数据分开判断。请求失败保留筛选输入并提供重试，旧请求不能覆盖最新查询结果。

BaseChart 的完整参数、按需注册、配置范例及可运行示例见 [图表组件文档](components/charts.md)。

## 接口和业务规则

前端在 `web/src/api` 声明类型，统一使用 `@/utils/request`。请求路径相对于 `/api`，成功响应已解包为 `data`，分页结果直接为 `{list,total}`；错误提示和登录续期复用现有拦截器。详见 [API 契约](api-conventions.md)。

后端 handler 接收明确 DTO，service 负责字段与引用校验、状态转换、数据归属及事务，查询/详情/更新/删除/统计使用一致的数据范围。更新区分未提交与合法的 0、false、空值。涉及竞争的状态操作按预期状态/版本做条件更新，需要共同成功的写入使用同一个事务实例。

会重复扣减、创建订单或调用外部系统的动作，按业务语义设计服务端幂等；普通 CRUD 沿用既定语义，不必引入通用流程引擎。第三方副作用不能被描述成数据库事务可以自动回滚。

增量修改保留人工代码和历史数据，新增字段/约束同时说明默认值、回填和兼容性。源码、Schema、迁移、构建及发布分别报告状态，已有表或菜单冲突不通过删除数据强行绕过。

## 试用任务与验收

可给已绑定技能的智能体以下需求：

> 基于现有后台生成维修工单管理页，支持状态/负责人查询、新增编辑和详情。草稿可提交，已提交不能删除，完成时必须填写处理结果。增加按日期和负责人筛选的每日完成量折线图及状态分布图。保留已有数据和人工代码。

检查结果是否包含：同一业务规格与稳定字段/动作 key、真实组件用法、前后端状态校验、归属过滤、表单失败保留输入、聚合接口与统计口径、增量数据影响，以及与工具实际执行情况相符的交付状态。

注册和装配测试使用隔离内存库与 mock 模型网关，验证技能保存、重复启动保留人工修改/原绑定、绑定后正文进入模型请求和解绑后不再注入。它验证装配链路，不等同于真实模型已完成一次业务开发验收。

提示词源文件位于 `server/internal/initialize/skills/`；初始化入口位于 `generation_skills.go` 和 `chart_skill.go`。
