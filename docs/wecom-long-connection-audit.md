# 企业微信长连接官方要求核对清单

核对日期：2026-11-06。来源为重新获取的[企业微信《智能机器人长连接》正文](https://developer.work.weixin.qq.com/document/path/101463)，页面标注最后更新日期为 **2026/10/10**。

本次按官方正文检查了当前文字问答范围，并修复下列偏差。结论限定为单实例管理一个 Bot ID 的文字问答接入；不表示已实现整页全部可选能力。实际企业凭据、网络和收发仍需单独联调。

## 当前核对结果

| 检查项 | 当前实现与证据 | 结论 |
|---|---|---|
| Bot ID/Secret、订阅与明确 ACK | [传输实现](../server/internal/wecomws/client.go)、[mock WebSocket 契约测试](../server/internal/wecomws/client_test.go) | 通过本地验证 |
| 30 秒业务心跳、断线重连、接管停止、取消 | 同上；认证失败不持续订阅，被接管后不抢连 | 通过本地验证 |
| req_id 透传、同请求串行 ACK、旧连接隔离 | 回答绑定原请求和连接代次，未知发送不重放 | 通过本地验证 |
| 每会话 30/分钟、1000/小时 | [持久化滚动额度](../server/internal/service/ai_bot_wecom_rate.go)、[分钟/小时/并发/重启测试](../server/internal/service/ai_bot_wecom_rate_test.go)；群聊不同成员共享配额，所有 stream 帧保守计数 | 本次补齐并验证 |
| 结束流不可再更新 | 成功 finish ACK 后拒绝直接或已排队的刷新；处理中和已完成的重复 msgid 均不另发流 | 本次修正并验证 |
| 过载流唯一性 | [业务实现及测试](../server/internal/service/ai_bot_wecom_test.go)按独立消息分配随机 stream ID，繁忙消息也持久化去重 | 本次修正并验证 |
| 24 小时与 10 分钟分别计时 | 回调首次收到后 24 小时内才可回复；stream 从真正首发起 10 分钟内可刷新；超窗帧在实际出队前再次拒绝 | 本次补齐并验证 |
| 非普通来源 | 出现 compat_info 即忽略，不将智能助理或频道消息当普通用户问答 | 本次补齐并验证 |
| 真实平台收发、配额与网络恢复 | 未使用实际企业凭据发起联调 | 待真实平台验收 |

原实现每秒刷流且没有统一会话额度、重复回调重发已结束 stream、繁忙回复固定使用同一 ID；这些行为已移除。当前中间刷新最多每 5 秒尝试一次，额度不足时跳过，首帧和终结帧等待额度；业务总期限为 9 分钟，模型执行及排队最多 90 秒。额度记录采用 UTC 并保存在数据库，重启及 Secret 轮换不重置。

本地验证覆盖 Go 测试（含 race）和 go vet；本次未修改前端业务代码。下表保留逐条官方要求，方便后续扩展欢迎语、卡片、媒体或主动推送时继续检查。

## 必须遵循的连接与文字消息协议

| 项目 | 官方要求或约束 | 性质 | 核对重点 |
|---|---|---|---|
| 连接凭据 | 在 API 模式选择长连接，使用长连接专用 BotID、Secret；旧回调模式的 Token/EncodingAESKey 不能替代 | 连接前提 | 表单字段、密钥保密、旧记录迁移 |
| 连接模式 | 长连接和接收消息回调地址二选一；切换会使原模式失效 | 平台约束 | 企业微信不能同时保留两套有效接收路径 |
| 地址 | 使用 `wss://openws.work.weixin.qq.com` 建立 WebSocket | 协议入口 | TLS 出站、握手完成后再订阅 |
| 订阅 | 握手后发送 `aibot_subscribe`，包含唯一 `headers.req_id` 与 `body.bot_id/body.secret` | 必填协议 | 每次新连接认证，未认证不处理业务消息 |
| 订阅响应 | 响应透传 `req_id`，仅显式 `errcode=0` 表示成功 | 成功条件 | 错误或缺失字段不误判认证成功 |
| 订阅频率 | 订阅接口存在频率保护，成功后不要反复发送订阅 | 平台限制 | 已建立连接不能由普通轮询持续重订阅 |
| 连接数量 | 每个机器人同时只有一个有效连接，新订阅会替换旧连接 | 平台限制 | 防止同 Bot ID 重复配置、多个实例反复抢占 |
| 心跳 | 定期发送业务 JSON `cmd=ping` 和唯一 `req_id`，用响应关联结果 | 必需保活 | 不能仅依赖 WebSocket 控制帧 Ping/Pong |
| 心跳周期 | 页面建议间隔为 30 秒，长时间未收到心跳会被平台断开 | 官方建议及平台行为 | 定时器生命周期、超时检测、退出取消 |
| 重连 | 开发者实现断线检测及自动重连 | 必需恢复行为 | 网络失败重试与取消；重新建立连接后重新订阅 |
| 被接管 | 旧连接收到 `aibot_event_callback`，其中 `body.event.eventtype=disconnected_event` | 平台事件 | 避免两实例不断踢掉彼此；主备方式由业务层协调 |
| 消息回调 | 命令为 `aibot_msg_callback`；`body.msgid` 用于排重 | 消息协议 | 原子持久化去重，不能重复触发模型 |
| 发送者身份 | `from.userid` 可能是明文，也可能是企业主体下加密值，取决于机器人创建者身份 | 身份语义 | 当作外部不透明身份，不自动等同内部账号 |
| 会话身份 | `chattype=single/group`；群聊回调含 `chatid` | 消息协议 | 上下文隔离与平台会话频控是两个不同维度 |
| 非普通来源 | 出现 `compat_info` 表示非普通用户消息，当前列出 `ai_assistant/channel` | 来源边界 | 未支持对应协议时明确忽略，不能无条件按普通用户消息处理 |
| 普通回复 | 使用 `aibot_respond_msg`，透传该消息回调的 `req_id` | 回复协议 | 不为普通回复重新生成 `req_id` |
| 回复响应 | 回复响应同样以透传 `req_id` 和显式 `errcode=0` 作为成功依据 | 成功条件 | 等待明确 ACK；失败及不确定发送不盲目重放 |
| 可回复时间 | 消息回调后 24 小时内可向该会话回复 | 时间上限 | 更短的业务超时可以使用，但不能发送过期回复 |
| 会话发送频率 | 回复和主动发送合计，每会话最多 30 条/分钟、1000 条/小时 | 强制频控 | 群聊按同一 `chatid` 合并不同成员，不能只按个人上下文计数 |
| stream 首发 | 新 `stream.id` 会创建新流式消息，后续同 ID 更新已有消息 | 流式协议 | 同一回答的 stream ID 固定，内容使用完整累计文本 |
| stream 关联 | 同一消息回调的首次和所有刷新使用相同 `req_id` | 必填关联 | ACK 串行匹配，旧连接任务不能借新连接误发 |
| stream 完成 | 设置 `finish=true` 后不能再更新该消息 | 状态终结 | 完成后重复回调不能继续刷新已结束 stream |
| stream 时限 | 从首次发送起，所有刷新及结束需在 10 分钟内完成，否则平台自动结束 | 时间上限 | 不能把回调收到时间和 stream 首发时间混为一谈 |
| 主动刷新 | 长连接不再提供 stream 轮询刷新回调，由开发者推送更新 | 接收模式 | 不能继续依赖旧 HTTP stream 轮询 |
| 组合及图片项 | 当前正文不支持 `msg_item`，也不支持 stream 与模板卡片的组合回复 | 当前协议限制 | 不应仅按 SDK README 的更宽能力描述发送此类组合 |

以上对应官方正文中的“长连接配置说明”“订阅请求”“接收消息回调”“回复普通消息”“流式消息回复机制”“保持心跳”各节。[原文入口](https://developer.work.weixin.qq.com/document/path/101463)

### 时间与频率的解释边界

- 官方对心跳写的是建议 30 秒；页面未规定客户端必须采用几次丢失 ACK、固定几秒超时或哪种退避算法。这些属于实现策略，不能包装成官方强制数值。
- 当前页面没有写流式刷新不计入会话频控的豁免。在未取得进一步官方依据前，保守实现应把每次回复发送纳入同一会话的分钟和小时配额，避免一秒一刷直接超过 30 次/分钟。
- 24 小时是普通回复的会话窗口；10 分钟从流式首发计算；下述 5 秒只适用于欢迎语和卡片更新，不能套用到普通文字回答。

## 当前文字问答范围之外的可选能力

下列功能是平台支持的接口，并不意味着一个仅提供文字问答的接入必须全部实现；应明确产品范围，不能宣称已经支持整份文档的全部能力。

| 能力 | 官方补充约束 | 本次核对范围 |
|---|---|---|
| 进入会话欢迎语 | `enter_chat` 后使用 `aibot_respond_welcome_msg`，须在 5 秒内发送 | 未开放欢迎语时可忽略；实现后必须遵守时限 |
| 模板卡片更新 | 对 `template_card_event` 使用 `aibot_respond_update_msg`，须在 5 秒内发送 | 当前非文字问答能力 |
| 图片、图文混排、语音、文件、视频 | 页面列出这些回调类型，部分仅支持单聊；资源 URL 5 分钟内有效，每资源有独立 aeskey | 当前不处理媒体，不应触发模型或下载 |
| 主动消息 | `aibot_send_msg`；须先由用户在会话中给机器人发过消息，才可向该会话主动发送；共享会话频控 | 当前不开放主动推送 |
| Markdown | 内容为 UTF-8，正文列明最长 20,480 字节 | 当前采用 stream；stream 内容 schema 应同时核对正文链接的消息格式定义 |
| 素材上传 | 会话 30 分钟；分片最大 512 KB、最多 100 片；临时素材有效 3 天；机器人上传频率 30 次/分钟和 1000 次/小时 | 当前不上传素材 |
| 智能助理与频道来源 | `compat_info` 标识来源；智能助理可能需要 `to_ai_assistant` 扩展 | 当前普通用户文字问答应与这些来源分开 |

## 需要单独保留的验收证据

1. Mock WebSocket 应验证订阅、唯一请求标识、明确 ACK、心跳、断线重连、接管后停止、取消释放和跨连接晚回复拒绝。
2. 业务集成测试应验证外部 Bot ID、会话和发送人隔离，消息去重，结束流不再刷新，以及按真实平台会话聚合的分钟/小时频控。
3. 配置页与接入文档应写明当前只支持文字问答，其他能力保持未开放。
4. 真实企业凭据下仍需验证订阅、单聊、群聊、网络恢复及平台实际频率错误；本地 mock 不能替代这些平台验收。

文档/智能表格的业务授权另见[官方文档使用说明](https://developer.work.weixin.qq.com/document/path/101468)和[项目授权说明](wecom-authorization.md)。该授权与本页 WebSocket Bot ID/Secret 连接认证分开，不是长连接协议的替代项。
