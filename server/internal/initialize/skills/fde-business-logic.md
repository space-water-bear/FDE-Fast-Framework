# FDE 业务逻辑开发

为 FDE Gin + GORM 后端及 Vue 3 页面新增或修改业务操作、校验、状态流转、关联保存和统计接口时使用。围绕同一业务规格实现页面与服务端行为，保留已有数据、接口约定和人工代码。

## 业务规格

先结合需求和已有代码整理：实体与字段类型、关系及引用约束、操作稳定 key、允许的状态转换、校验规则、角色与数据归属、接口输入输出、验收案例。字段、按钮、接口和状态使用稳定标识，显示文案不承担操作识别。只追问会改变业务结果的缺失信息，其余按已有约定继续并说明假设。

每个操作说明前置条件、允许角色及记录范围、成功后的字段/状态变化、失败时保持的状态和是否允许重复执行。例如 `complete` 仅允许从指定状态进入完成，必须有处理结果；页面提示与服务端拒绝条件一致。状态枚举和显示标签从同一规格映射。

Schema 工具字段用小写 snake_case，接口 JSON 遵循现有 camelCase，模型、表单与 DTO 之间建立明确的双向字段映射；沿用已有字段时保留兼容，不能仅为统一命名而重命名旧数据。

## 页面与组件协作

- `TablePage` 负责列表查询、分页与操作入口；`FormRender` 渲染 Schema 字段和联动，公开 `validate()` 与 `clearValidate()`。业务页面显式初始化默认值并校验提交，额外联动和规则由业务代码处理。
- 页面调用 `web/src/api/*.ts` 的类型化函数，复用 `@/utils/request`；该请求器自动携带令牌、成功后返回 `data` 本体、统一处理刷新及错误提示，业务代码不再读取 `response.data.data` 或重复弹同一失败消息。分页返回 `{list,total}`，参数为从 1 开始的 `page` 和 `pageSize`。
- 筛选后刷新相关列表/图表，防止旧请求覆盖新结果；编辑表单使用独立草稿。校验失败或提交失败保留输入，成功后按操作语义刷新列表、详情和统计。提交中禁用对应按钮，失败后恢复。
- ECharts 复用 `@/components/charts` 的 `BaseChart` 与现有配置函数，组件管理实例，页面负责请求与字段映射。统计接口按权限和筛选聚合全量数据，不能使用当前分页冒充全量；明确指标、币种、退款、时区与补零规则。分转元仅在展示边界执行，`hasData` 与金额 0 分开判断。

## 后端权威规则

handler 解析和校验请求 DTO，调用 service 后以 `utils.OK/Fail/Forbidden/NoAuth` 返回 `{code,msg,data}`；成功为 `0/HTTP 200`，业务失败为 `40001/HTTP 200`，无权限为 `40003/HTTP 403`，未登录为 `40004/HTTP 401`。新增业务路由接入 JWT + Casbin，并补菜单、按钮的路径和方法授权；数据归属约束仍须由业务查询落实。

service 同时校验必填、类型、范围、引用是否存在及可访问、状态前置条件。页面显隐和前端规则仅提供操作反馈，直接 HTTP 调用也必须得到相同约束。身份、归属、审核人等服务端字段从可信会话和现有记录派生，不接受请求覆盖。创建和更新仅映射允许修改的字段；区分“未提交”与“设为 0/false/空值”，避免 GORM 更新跳过合法零值。

列表、详情、修改、删除和统计使用一致的数据范围。带 ID 的写入同时约束记录归属，检查实际影响行数并返回明确结果；不能只在读列表时过滤。金额沿用整数最小货币单位或项目既有精确类型，时间保存与业务日分组明确时区和区间边界。

## 事务、并发与重复操作

主从保存、库存/余额变化等需要共同成功的写入放在同一数据库事务，内部函数传递并使用同一 `tx`，任一步失败返回错误以回滚。事务外通知或第三方调用需说明失败与重试语义，不能把外部副作用描述成数据库可自动回滚。

存在并发竞争的状态动作，用记录 ID、归属及预期状态/版本作为更新条件，检查影响行数，避免“先查状态再无条件更新”。会产生重复订单、扣减或外部副作用的操作，按业务设计稳定请求标识、唯一约束或其他服务端幂等保障；同一标识重试核对请求内容并返回既有结果。普通可覆盖 CRUD 沿用其已定义语义，无需引入通用流程引擎。按钮禁用不能替代服务端保障。

## 生成与增量修改

普通会话提供 `generate_form_schema` 草稿与 `generate_business_code` 基础 CRUD 预览，写盘由用户审阅批次后执行。开发工作台在隔离任务中生成新业务源码、FormRender 表单 Schema 和安装资产，按源码哈希应用本任务的修改并运行固定检查。当前首次交付面向基础单表。关系、状态转换、事务和数据归属按业务规格用代码和测试落实。遇到已有表、菜单或人工改动冲突时保留数据和代码，按版本化增量流程处理。

Schema 保存替换完整字段集合，`mode:update` 不是局部补丁；先读取完整旧对象，合并保留原字段和规则，保存后复核。生成代码 dry-run 仍保存审计，不能将“不写源码”当作无持久化副作用的只读操作。

新增字段与约束说明历史数据默认值/回填及兼容性，保留原自定义规则。源码变更、Schema 保存、迁移和应用发布分别记录结果；具体迁移和发布沿用项目权限及交付约束。工具缺少文件编辑、测试或部署能力时产出可审阅代码、操作计划及待执行项，不把保存技能或生成文本当作完成业务交付。

## 验证与交付

按业务风险验证正常流程、非法输入/引用/状态、无权限与跨归属访问、合法零值修改、提交失败保留输入；涉及事务或竞争时加入中途失败、重复请求和并发状态冲突案例。统计核对汇总与各图表口径一致。使用环境实际提供的工具运行受影响测试、类型检查与构建，并记录结果；未执行的检查明确列出。交付说明规格、接口/菜单/Schema/源码变更、数据影响及验证证据，区分已实现、已验证和待部署。
